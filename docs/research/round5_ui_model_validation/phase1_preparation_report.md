## 对照、冻结与评分工具

冻结主要指标见 PROTOCOL.md（仅本机证据：`experiments/round5_ui_model/PROTOCOL.md`；不随 Git 分发）。每例每条件独立新对话，各收第一份回答；同一产品/界面模型/思考设置/工具权限。共用 600 字符要求、相同公开事实，S2 仅增加最多两候选、事实/假设分离、待定、区分追问和不直接交付完整修复等约束。奇数先 S1，偶数先 S2；不得用重新生成后的好答案替换失败。

UI 无法精确控制或观察后台版本、温度、token 预算，相关字段 unknown；只能比较操作者报告的同界面设置，不能声称严格 API 参数等价。记忆、全局指令、项目资料和工具读取若无法隔离，配对标探索性。收集工具不会自动证明产品实际上下文干净。

版本链依次为：主冻结清单（公开案例、gold、模板、提示和协议）、在 S0 前的标注/规则附录（具体泄露例子与既有 S0 问题），以及在 UI 回答前的工具实现冻结。主文件未覆盖；具体根因和评分口径没有在 S0 后重定。历史资料清单含 271 个文件，检查器逐一核对。

自动流程已实现：

- collect.py：一次设置登记、收件清点、逐份元数据、字节原样归档、重复导入去重、保留首次主输出和追加尝试。
- analysis.py / score.py：只解析 JSON 或人工原文引用的原提交预测，排除非法输入，对冻结代码实际执行；不运行模型代码、不用模型给自身教学质量打分。
- 人工评审模板：原因的语义 ID、确定/暂定、待定范围、问题两条回答路径、无依据知识确认、完整泄露/部分补丁、额外步骤；必须引用原文。未完成字段不汇总为成功。
- validate_package.py：历史 SHA、冻结链、公开字段、输入合法性、证据与执行日志一致性、同上下文、标签/私有参考隔离、S0 数量、阶段一 0 原文/0 分析。

分母同时保留每组计划 8 例与 8 个规范根因；未作答、失败、截断和人工待评审均单列。普通 AI 不用 JSON 的正确自然语言预测可由人工引用后规范化，不能把结构遵循当教学增量。合理待定可以是对学生知识的待定，同时准确判断程序原因；在完整代码已有充分证据时全部拒判程序原因须检查是否过度保守。不存在一律待定即可赢的单项安全分数。

测试夹具仅在临时单元测试目录，不写项目 responses 或正式模型结果。测试日志保留开发阶段预期的缺模块/缺函数失败（tests_red_01/02/03）及收件版本冲突的回归失败（tests_red_04），随后通过的 15 项收集/解析/评分工具测试；失败没有删掉。版本冲突测试确认显式登记首次主输出后可以保留两个收件文件，后续导入也不会替换主输出。评分链路测试在临时目录核验一个明确标为单元夹具的预测，确认程序输出核验成功仍不会生成原因或教学质量成功评分，S0/S1/S2 的主观字段保持待评审。最终检查的命令与日志以 results 中对应文件为准。
