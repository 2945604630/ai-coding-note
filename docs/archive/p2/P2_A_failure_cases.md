# P2-A：失败、争议与局限

日期：2026-10-11。**核心失败是没有观察到选择器相对强基线的增量。** 另外，设计签名不足以识别真实认知，单动作金标准偏窄，本轮还发生了一处 F03 适配字段错误。首次记录均保留，没有重新生成、改评分或扩展案例来改变结论。

运行与对照见 [P2_A_probe_feasibility.md](<P2_A_probe_feasibility.md>)，停止决定见 [P2_A_next_decision.md](<P2_A_next_decision.md>)。

## F01：选择器在两个场景都重复了强基线的选择

| 场景 | A | 普通优化 Prompt B0 | 预设强树 B1 |
|---|---|---|---|
| C03 补偿性错误 | 追踪循环结束值与返回关系 | 同一问题、同一文本 | 同一问题 |
| C01 “应该”与实际行为冲突 | 追踪范围、累加、含义 | 同一问题、同一文本 | 同一问题 |

这不是“大家都表现好，所以新机制成功”。拟议增量是选择决策，强基线已经完成它。A 初始 AI 映射也保留全部候选，与事前标签一样，未改变选题。即使后续有措辞优点，也不能因此宣称选择器更有价值。

范围有限：本轮不证明所有主动探针都无价值；但已经足以否定**用这两个小任务及当前签名规则支持独立创新投入**的主张。没有理由以“还需要更多案例”为由自动扩大六类测试。

## F02：人为分区不是认知可识别性的证据

选择器的输入形式是 `hypothesis -> one response_signature`。例如 C03 三个解释分别对应“只按循环”“只报数值”“解释关系”，因此算出最大剩余1。这个映射是作者假设，没有学生数据校准，也没有证明真实学生会按这种方式回答。

冻结材料自己就包含 R4：不确定或不想猜。该回应与三种解释都相容，剩余解释仍是3。因此，**真正包含未知回答的最坏情况不是1**。不能将 `worst_remaining=1` 报成已获得的认知信息增益。

其他未解决的重叠包括：

- 不理解的人可能直接复述给出的输出，甚至复述关系解释。
- 理解的人可能不愿展开，或者表述仍含糊。
- 对循环与返回有部分理解的人，可能同时满足 H1/H2 的描述。
- 正确数字不能单独支持“已经理解”；当前明确解释也不等于稳定掌握。

本轮实际可靠的对象只是“这句回答说了什么，以及哪种后续动作与它相容”。selector.py（仅本机证据：`experiments/P2_A_probe_feasibility/selector.py`；不随 Git 分发）始终保留认知解释未证实，不以输出证明真实心理状态。

完全不可区分的负控里，各题签名全相同，选择器返回 None；这证明它没有在该负控下伪造分区，但不修复上述签名模型本身的不足。

## F03：动作精确匹配会虚构 A 的优势

冻结标准给每分支只写了一个动作。A/B1 按同一表查出动作，8/8匹配是构造性质；B0自由响应只有6/8匹配。以下两个“不匹配”都不能直接判错误：

| 分支 | 冻结标签 / A | B0 的实际行为 | 为什么不能判 A 获胜 |
|---|---|---|---|
| C03 R4：不确定、不想猜 | clarify_meaning | suspend_for_choice，让学生决定暂停或继续 | 尊重拒绝猜测可能更合理；两者都保留未知 |
| C01 R2：把累加当覆盖 | continue_asking | show_counterexample，对照实际3后询问累加与覆盖区别 | 同样聚焦当前新增误解，没有重复已说明的范围 |

本轮没有事后把标准改成多个动作，也没有把两个差异算成教学失败。字段差异保留，语义判定待独立人工审查。对照原文见 live_reply.json（仅本机证据：`experiments/P2_A_probe_feasibility/live_reply.json`；不随 Git 分发）。

将来若恢复研究，应在调用前冻结“动作允许集合＋所需教学焦点＋停止/未知边界”，不能只靠单个 action enum。当前不因评分标准偏窄而重跑模型。

## F04：F03 命题适配字段错误，九条正式核验均为未知

本轮脚本传入：

```json
{"kind": "output_equals", "expected_output": 8}
```

现有 F03 需要 `value` 字段。本轮写错了适配，九条正式命题状态都为：

```text
inconclusive / not_an_executable_predicate_or_missing_value
```

例如 C03 E6 原始结果（仅本机证据：`experiments/P2_A_probe_feasibility/evidence/C03_E6/result.json`；不随 Git 分发）确实执行并取得 actual_output=8、reference_output=6，但 verification.status 为未知。

**影响边界：**

- 九次真实运行及其 source/version/hash、实际输出、参考输出未因此失效。
- 离线基本门槛采用的是实际输出和参考输出对冻结值的逐项比较，9/9一致。
- 不能宣称九项归一化命题“supported”，也不能宣称该适配器整体通过 F03 验收。
- 它没有决定三方法的不同选题：三方法收到的是共同冻结历史事实，原样一致；没有给 A 独享核验数据。

该错误说明适配器检查不够完整。没有改写原始 request/result，也没有追加执行取得“通过版”。停止后保留首版脚本和失败材料；若用户以后授权恢复，应先修正字段、冻结修订，并单独标记重跑，而不是混入本轮成功计数。

## F05：AI 映射没有显示必要性

A 在两条最初回应上保留全部解释，在八条后续显式回应上与作者预设标签一致。这只说明模型可以识别这些句子的明确内容。它没有显示优于真人教师或人工标签，也没有显示在复杂自由表达上节省标注成本。

学生分支是本对话 Codex 编写的，含“只是复述”“不确定”“我以为替换”等直白信号；不是自然学生语料。标注者也是同一作者，独立人工审查为0。B1 的冻结标签不是实际教师现场判读结果，不能声称真人教师零成本达到同样效果。

对这两个已知程序，用固定问题和透明分支就能完成决策。AI 可以作为语言接口，但现有证据不支持它是探针选择不可替代的部分。

## F06：预算和语义仍有待审部分

初次问题相同，代码、运行事实及回应项目上限相同；各分支最多一个后续动作/提问回合，没有新增执行或完整修复。模型后续消息措辞不同，B0 多展开了局部概念和边界提示。

“没有完整代码”不等于“帮助暴露强度完全相等”。局部思路提示、复述学生已给解释与新的概念引导如何区分，仍待人工审查。本轮不把这部分归为0争议，也不依据消息长度判教学优劣。

B0 初始从共同题库选择，不能代表开放式聊天 tutor 的全部能力；A 后续生成标签，B0 生成完整导师消息，所以耗时/输出 token 差异不能称算法效率增量。两案和八分支批量放入各阶段调用，不能当作十个独立试验，更不能计算可信显著性。

## F07：真实调用有传输告警，计费与后端快照不完整

四个 CLI 均完成一个回合，合计28条非致命告警，包含 WebSocket超时、回退HTTPS和自动重连。首次最终结果未重采样，但底层网络请求次数不止能够证明的四个CLI入口；实际请求数和费用分摊未知。

请求模型名和 effort 两方法相同；实际服务端模型快照未被独立证明。输入43,296、输出4,093 token 是 CLI usage 汇总，不是独立计费账单。没有修改全局网络、模型、登录或实验性功能配置来优化本轮表现。

旧传输在 `public=None` 时默认写“辅助评审”来源标签；本轮 wrapper/frozen 清楚说明真实任务为映射或导师响应，没有 AI 互评。不能因复用传输的旧标签把本轮认作独立教学审查。

## 终止理由

不是模型不能提问，也不是所有证据教学都无价值。**当前新选择器只是用未经校准的签名，选中了强 Prompt 和简单树已经会选的问题。** 动作改变可由同一固定分支完成，两个评分差异又不足以支持优势。

这些证据足以停止当前方案的完整开发投入。没有真实学习者、真人教师审查、对自然表达的必要 AI 增量或可靠认知区分证据，不宣称教学效果、迁移提升或创新成立。
