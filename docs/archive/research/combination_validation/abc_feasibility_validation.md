# A／B／C 技术可行性与静态案例验证

日期：2026-10-08。**本文件包含设计级分析与十个静态案例，未执行案例代码、调用模型开展实验、运行上游程序或制作原型。** 所写“预期输出”来自题目定义与手工推理，不是已采集运行结果。运行器、核验器、数据类型和接口均为拟议设计。比赛截止时间不影响判断。

## 1. 共同原则：三层判断不能互相替代

| 层次 | 可作为依据的内容 | 允许结论 | 不允许跳跃 |
|---|---|---|---|
| 执行事实 | 后续真实采集的代码 hash、输入、运行环境、stdout／stderr、用例与预言机版本 | 此程序在这次有效运行和这个输入上输出 X／超时／失败 | “程序在所有输入都错”“学生不懂概念” |
| 程序原因假设 | 有限规则、数据流位置、可反驳预测、区分性输入、修复前后对照 | 某假设被反例反驳，或在限定范围得到支持 | 有测试通过就证明该自然语言解释正确；修好就找到唯一根因 |
| 学习者理解假设 | 用户解释、状态预测、诊断问、新题作答和辅助记录 | 某误解在指定任务中获得支持，或仍未确认 | 代码中出现某 bug 就证明学生持有同名误解；模型 confidence 就是真实掌握 |

静态案例中，“给定事实”只指列出的代码、输入、题意、假设操作记录；真实运行输出仍待采集。若后续实际运行与手推不同，首先检查运行环境、代码版本和预言机，不修改事实迎合模型。

### 拟议的最小数据契约

| 记录 | 关键字段 | 接受条件 |
|---|---|---|
| `ProblemSpec` | 题意版本、函数协议、输入前提、概念与题族、可信预言机来源、测试版本 | 未审核题意／参考来源不得成为独立验收题 |
| `ExecutionEvidence` | attempt／run／case ID、代码与题包 hash、runtime、实际结果、预期来源、完整性 | 环境失败、超时、截断与 WA 分开；超时不杜撰实际输出 |
| `ProgramHypothesis` | 结构化断言、引用 ID、预测关系、反证、状态、范围 | 引用有效≠原因成立；允许 proposed／supported／refuted／inconclusive／stale |
| `GapHypothesis` | concept／misconception、诊断问、用户回答、支持／反证、确认规则版本 | 不由 ProgramHypothesis 自动升级；confirmed 仍限定概念与任务范围 |
| `AssistanceEvent` | 题目／题族、提示或补丁内容类别、时间、来源、暴露范围 | 不能仅保存 hint_count；精确修复建议也是辅助 |
| `LearningObservation` | 首次新题尝试、评分依据、题族暴露、辅助状态、失败原因、资格 | assisted／independent／unknown 分开；一次独立通过不写成长期 mastered |
| `ExerciseValidation` | 每项检查 pass／fail／not_checked／inconclusive，版本、预言机、目标变异体 | 任何必要检查未完成不得输出完整教学合格；只能声明检查覆盖范围 |

生成的预期输出、用户确认、模型解释分别标注来源。模型不得直接写入事实、confirmed 或独立观测；状态规则是普通程序逻辑。更正诊断用追加事件撤销关联推荐和结论，保留历史，不静默删除旧证据。

## 2. 方案 A：错误诊断与迁移学习

### 2.1 最小完整机制

失败提交由 B 形成有限的程序原因候选。只有用户在有区分力的诊断问中表现与某误解一致，才形成限定的知识漏洞确认；无法区分时保留待定或由用户选择训练概念。②选取人工审核的同概念、不同任务题；③在答案与提示未暴露的题族上记录新题首次独立观测。未通过则回到诊断或训练；运行环境问题不记认知失败。

这比现有项目应增加的是**观测资格和状态传播规则**，不是再做错题表、BKT、推荐页。OpenTutor 已有[提交—分类—派生—概念状态链][ot-submit]及[两题对照诊断][ot-wa]；SmartCode 已有[提示扣分与技能更新后推荐][sc-submit]。若新机制只是把这些步骤换名串起来，差异不足。

### 2.2 防止错误诊断导致错误训练

训练选择器只接收确认规则已满足的 `GapHypothesis`，并检查其依赖的题包与运行版本仍有效；程序原因支持与人的误解确认分两个状态。多原因竞争时用固定追问区分；用户给出正确概念解释时，不强行确认漏洞。跨题表现矛盾时降低确认范围或撤回；不能让粗标签重复次数替代确认。

“不懂循环”过于宽泛。首批可限定初值假设、循环端点、累加与覆盖、列表别名等 3～4 个可区分错误族。需要小型人工标注与专家审题，不需要大规模训练模型。taxonomy 是否适合真实学习者仍需验证。

### 2.3 独立检查的可证明范围

题意、测试、概念对应先人工确认；训练题与验收题按题族隔离，不能仅换数字就称迁移；关闭该次目标题的应用内 AI 提示，保存首次尝试，后来请求帮助则转 assisted。学习者声明是否使用外部工具；无法判断时记录 unknown。普通个人应用不能证明从未使用外部 AI。

首测通过可记录“本任务独立通过观测”；延迟新题、不同表征与多次一致表现才支持更强结论。自然语言解释可由量表与人工复核，不把另一轮 LLM 打分当独立真值。FSRS 只安排复习，不能将其稳定度解释成编程能力。

### 2.4 A 的三个静态案例

#### A1：正常路径——初值假设得到有限确认

题意：非空整数列表求最大值。用户提交下面的研究示例，并在之后回答诊断问。

```python
def largest(xs):
    best = 0
    for x in xs:
        if x > best:
            best = x
    return best
```

- **输入／给定事实：** 题意允许全负数，给定 `[-5, -2]`；手推该代码返回 0，题意最大值为 -2。假设用户回答“0 可以作任何整数集合的初始最大值”。这些都是案例设定，尚无实际日志。
- **模块与传递：** executor 拟产生 E1；①引用 E1 和初始化位置提出“初值不满足范围”的程序假设；固定预测问区分“不理解初值”与偶发写错；①生成限定 Gap；②选择“求正整数列表最小值”的审核题；③选择另一未暴露题族独立检查。
- **设计输出：** 程序假设 supported；用户给定回答为误解支持证据；训练目标是“极值初值与数据范围”，不贴“循环能力低”总标签。训练和验收结果分开保存。
- **失败处理：** 若用户正确解释初值应来自列表，只记录 bug，知识漏洞保持待定；若预言机来源未审，则先冻结训练分配。新题困难也可能来自别的概念，不能自动强化旧诊断。
- **可实现性：** 固定题、确定性执行、诊断问和事件规则均可由成熟技术支持；迁移改善属于未验证假设。

#### A2：易误判——相同输出不能确定同一错因

题意：计算 `1 + … + n`，`n` 为正整数。

```python
def end_missing(n):
    s = 0
    for i in range(1, n):
        s += i
    return s

def overwrite(n):
    s = 0
    for i in range(1, n + 1):
        s = i
    return s
```

- **用户操作／输入：** 两位学习者分别提交上述函数，先给 `n=3`。手推两段都返回 3，题意为 6；看同一失败输出会很像。
- **模块与传递：** ①保存不同代码 hash，提出端点遗漏／累加覆盖等候选；对 `n=2` 手推分别为 1、2，而题意为 3，可作为拟议区分用例。②还不能按“求和错误”合并训练。
- **设计输出：** 程序原因分开；第一位回答 `list(range(1, 4))`，第二位回答逐步 `s = i` 与 `s += i` 的状态预测。只有回答支持时分别确认端点或累加误解；两人均解释正确时不确认认知漏洞。
- **事实／推断：** 代码、输入、手推输出是给定内容；“持有端点误解／覆盖误解”是待用户行为确认的推断。一个错因可有多种写法，多 bug 程序也不能强制单标签。
- **失败处理：** 若追问不能区分，输出 inconclusive，选通用复盘或人工确认；新增区分用例必须符合正整数前提且有可信期望。
- **可实现性：** 小型输入搜索与固定问题可以实现；从任意自然语言回答可靠识别误解仍有不确定性。

#### A3：关键区别——辅助修复成功不计独立掌握

- **用户操作：** 假设用户在 A1 原题中看到 AI 的精确修改“把 best 改成 xs[0]”，提交后全部审核用例通过。随后在无应用内提示的新题 `smallest(xs)` 中仍使用初值 0。
- **输入／预期：** 新题非空正整数列表 `[4, 7]`，题意答案 4；若代码用 `best=0` 和 `x < best`，手推返回 0。旧题 AC、新题失败是拟议实验中要采集的结果，不是本轮测得。
- **模块与传递：** ④保存精确修改暴露；①把原题修复记为程序层事实；③拒绝将该次原题记 independent，检查新题题族与辅助条件；②接收新题失败观测选择进一步训练。
- **设计输出：** 原题 assisted_success；新题 independent_failure（条件确实满足时）；不输出 mastered。若用户用了外部 AI 且不能核实，则 independence=unknown。
- **失败处理：** 若新题未审核、目标概念不同或运行失败，不记独立认知失败；若用户请求提示，本次改为训练，不能清空计数再补记首测。
- **可实现性与区别：** 事件资格可实现；相比自评、原题 retry 或提示扣分，独立观测规则更严格。其教学必要性与新题效度必须实验检验。

## 3. 方案 B：高可信诊断引擎

### 3.1 技术主线与真正难点

输入题意、代码、可信用例结果和版本；LLM 输出至多若干有限假设，每个给证据引用、可反驳预测、区分用例或追问。程序核验引用、版本、事实值及受支持的预测关系。不能验证的自由文本解释标为未核验，不用 confidence 替代支持证据。用户的理解问题另建 GapHypothesis。

[SmartCode `_overlay_sandbox`][sc-overlay] 已覆盖通过／失败和输出，但真正失败时可以保留模型既有解释；[Iris 锚点校验][iris-struggle] 已排除不存在文件行。B 的最低差异必须超越两者：有效引用上仍错误的解释要能被反证或保持待定；核验缺席要显式显示。

独立证据验证器有必要，但范围必须有限。首批可检验事实值、源码位置、简单循环范围／比较条件、可执行反例和假设预测；不能实现任意程序的自然语言因果证明。某补丁通过测试只能支持修复有效，不能证明唯一根因或人的认知缺陷。

### 3.2 独立产品与复用形式

面向初学者或助教的最小工具可以导入函数代码与题包，执行、生成诊断卡、提出追问、回放证据和验证用户手写修复，并导出审计记录。无需题库管理、画像或自动改代码。若只有后台 JSON 而没有提交—结果—处理不确定—复查的流程，产品完整度不足；但该 JSON 核心可以独立作为库／CLI／API 复用。

B 是否实用取决于它是否减少错归因而仍给出足够有效反馈。全部拒绝会降低错误断言，却没有服务价值，必须同时测正确诊断覆盖率、待定率、交互成本。

### 3.3 B 的三个静态案例

#### B1：正常路径——有效反例和修复对照

- **用户操作／输入：** 提交 A2 的 `end_missing`，题包固定为正整数求和；先检查 `n=2`，手推 actual=1、expected=3。
- **模块与信息：** executor 拟产生包含 hash 的 E2；①提出“range 不包含 n”的假设和有限预测；核验器检查实际循环范围及 E2；④问学习者预测 range 的元素；用户手写修复后 executor 在同版本测试集和额外边界输入回放。
- **设计输出：** 事实引用有效，端点假设 supported；修复在已检查输入上通过；学习者认知状态取决于回答，B 单独不宣布掌握。
- **失败处理：** 改题意或换测试版本必须创建新证据；修复后新回归失败则保留失败；模型不可用仍输出确定性测试报告。
- **可实现性：** 固定 AST／输入规则与普通执行即可；不限域推广不成立。

#### B2：易误判——合理的认知解释没有证据

- **用户操作／输入：** 提交 A1 代码；模型在给定案例中输出“你没有理解循环不变量，因此初值设成 0”，引用全负数失败输入。
- **给定事实／推断：** 代码初值、允许负数的题意和手推失败支持程序缺陷；它们不证明学习者不懂循环不变量。假设用户随后正确解释初值要求，并说自己沿用了前一道非负数题的代码。
- **模块与传递：** ①将程序初值假设和认知假设分别保存；核验器验证失败事实，无法验证人的理解断言；④使用固定初值预测问；确认器根据正确回答保留 Gap 待定／反证，不向②分配“循环不变量漏洞”训练。
- **设计输出：** “全负输入下初值不合适”得到有限支持；“学习者不理解循环不变量”未证实。用户自述也只是行为证据，不能反向证明其绝对掌握。
- **失败处理：** 不输出高 confidence 的确定认知标签；若用户回答不充分，提示需要更多观察；不以强行选一个错误族结束流程。
- **可实现性：** 分层状态和固定问可实现；复杂语言理解仍需复核。此例体现保持不确定的价值。

#### B3：关键区别——引用真实失败，也可以归因错误

- **用户操作／输入：** 再提交 `end_missing`，给 `n=3`。手推 output=3。模型引用真实用例却解释为“累加器每轮被 i 覆盖”，并给可检验预测“正整数 n 的最终输出总是 n”。
- **模块与传递：** ①不能因为 E3 存在且确实失败就批准解释；核验器检查当前源码 `s += i`，并在拟议新增用例 `n=4` 检查预测，手推输出为 6、题意为 10，模型预测为 4。引用、模型预测和真实采集待办分开。
- **设计输出：** 指定预测可被反驳，假设 refuted；端点遗漏可成为另一候选。若 AI 没给可检验预测或规则不支持，则输出 inconclusive，不假装已核验整段解释。
- **失败处理：** 若模型换用旧代码 hash、旧测试或捏造 E ID，标 stale／invalid 引用并拒绝；新例期望未经独立检查则不升级原因状态。
- **可实现性与区别：** 此受限反证可实现，能超越“实际 verdict 覆盖模型 verdict”。[HypoCompass][hypo] 已用行为区别帮助解释，所以这是针对实际提交与状态审计的工程差异假设，不能称反例检验思想原创。

## 4. 方案 C：针对错误的练习生成与质量验证

### 4.1 必需的独立闸门

| 顺序 | 拟检查对象 | 成熟方法 | 不能推出的结论 |
|---|---|---|---|
| G0 题意与前提 | 目标概念、函数协议、合法输入与边界 | 教师审核模板／有限 DSL；冻结 contract | 随便生成的题面有绝对真值 |
| G1 参考解 | 与独立预言机的结果一致 | 教师拥有的简单参考、有限枚举、性质／差分测试 | 参考解与自己生成的测试互相通过即正确；两个 LLM 一致即独立 |
| G2 用例有判别力 | 断言实际执行，目标 bug 能被发现 | 手写目标误解变异体＋测试 kill matrix；排除无效／等价变异体 | 高覆盖率证明测试质量；任意变异体被杀死证明覆盖目标误解 |
| G3 考查目标 | 题意和要求确实涉及目标，避免多概念污染 | 专家量表、已审模板、行为对照与学生试作 | reference 中含循环就证明学生练习了循环；模型标签是教学真值 |
| G4 可用于验收 | 未暴露题族、无答案进入训练上下文、评分协议固定 | 分区题库、暴露事件与版本审计 | 参数换名即远迁移；本地关 AI 即保证独立 |

“独立预言机”指题意来源与判定规则不由同一生成—修复过程随意更改；不同模型但共用错误题意也可能同错。小题可以枚举有限输入；一般算法不能靠有限测试证明全域正确。性质或第二实现也可能漏检，需说明覆盖范围。

目标变异体必须满足输入前提、能正常运行、确实改变规定行为，且与目标误解有人工可解释关系。timeout／编译失败、无效变异、等价变异不能简单算作成功杀死；目标变异体全部被捕捉仍不是知识点效度的充分证明。

### 4.2 单独产品与作为 A 辅助的差别

C 独立服务教师、助教或题库维护者，需要目标输入、候选题包、检查明细、人工审阅、有限修复、版本及来源导出。默认生成草稿，不自动发布题。Artemis 已有较完整的[变式生成核验][art]；C 若只做同样基础闸门，独立开发价值偏低。

作为 A 后台，仅需检查手工题包、目标误解变异体和受限参数变式；不需要教师账户、课程、考试组、题库商店、大规模生成流水线或第二套 UI。A 可先完全不启用生成器。C 的效果要和“人工模板＋成熟测试／变异工具”比较，不能只和裸提示出题比。

### 4.3 C 的四个静态案例

#### C1：正常路径——可审核模板与目标变异检查

- **用户操作／输入：** 教师选“严格大于与大于等于”，要求 `count_positive(xs)` 统计正数；题意由教师冻结为 `x > 0`，独立参考为逐项计数。生成器只改变背景和有限参数。
- **模块与传递：** ②的目标信息传给⑥；G1 对比独立参考；共享 executor 拟检查 `[]`、`[0]`、`[-1]`、`[2]`、混合列表；G2 对目标变异体 `x >= 0` 建立 kill matrix；G3 人工确认目标一致。
- **预期输出：** 手推 `[0]` 时正确参考为 0、变异体为 1，预计可拒绝目标错误；题包只在相应检查完成后 accepted，保留范围与审阅者。
- **事实／推断与失败：** 题意、输入和变异定义是给定；实际 kill 结果未取得。独立参考失败或人工检查缺席时 hold，而不降成默认接受。
- **可实现性：** 小型函数题、固定预言机和手写变异体容易拆开验证；并不证明自动审题普遍可靠。

#### C2：失败路径——能跑、参考通过、模板失败，测试仍无效

- **用户操作／输入：** 教师收到 C1 的 AI 题包，但生成测试仅含 `[1,2]`、`[3]`；参考采用 `x > 0`，starter 直接返回 0。
- **手推与边界：** 参考两项通过、starter 两项失败；目标变异体 `x >= 0` 也两项通过。基础构建闸门可成立，测试没有发现指定错误。
- **模块与传递：** G2 执行目标变异体检查，报告 surviving_target_mutant；⑥把报告送有限修复过程，新增由独立预言机确定的 `[0]` 等用例，再重新检查。不得修改“正数”的 contract 使变异体变正确。
- **设计输出：** 首个题包 rejected／needs_revision，不能标为针对目标错误的合格题；既有其他测试仍保存。
- **失败处理与可实现性：** 自动发现幸存变异体可以实现；人工排除等价变异。此例是相对 Artemis 式基础闸门的必要区别，但[EvalPlus 变异工具][ep-mut]已体现同类测试思想。

#### C3：关键区别——生成器的答案与测试一起错

- **用户操作／输入：** 教师冻结“正数为大于 0”，模型却生成 `x >= 0` 的参考解及把 `[0]` 的期望写成 1 的测试；题面仍称“正数”。
- **模块与传递：** G0 保存原 contract；G1 对同一输入调用教师参考，手推为 0；共享执行记录保留生成参考与独立参考两个输出来源；⑥记录 oracle_conflict，不能让修复 Agent 修改教师参考。
- **设计输出：** rejected；题面、参考与测试共同一致不作为接受依据。多模型投票也不能覆盖教师冻结规则。
- **失败处理：** 若没有可信参考，则人工审核／inconclusive；不把“无冲突发现”写成“已证正确”。纠正参考后重查全部用例和目标变异体。
- **可实现性与区别：** 冻结参考与差分可实现；这超越自生成自验证，但独立 oracle 是既有评测原则，[EvalPlus 的 canonical solution 路径][ep-eval]已有先例。

#### C4：失败路径——运行正确却偏离目标知识点

- **用户操作／输入：** 教师选“二维列表共享引用”；模型生成“统计列表里正数”题，参考与测试都正确，metadata 却标 `list_aliasing`。
- **模块与传递：** G1／G2 的普通测试可通过；G3 对照目标量表，题意没有可变嵌套对象或共享状态，无法用目标别名变异体展示行为差异。②不应消费此题来训练共享引用。
- **设计输出：** concept_mismatch 或 inconclusive，禁止作为该目标的训练／验收题。可以降为另一个经过审阅的普通题，但需重新标注和审核。
- **失败处理：** 不靠换标题、加标签或让 LLM 自称“涉及列表”通过；请求教师审阅或返回已审的二维表模板。
- **可实现性：** 在有限模板中可通过规则与审核实现；任意题目教学目标的自动真实性没有可靠通用保证。这是 C 最大的不确定点之一。

## 5. 指定开源技术的复用与成本

| 技术 | 实际读到的基础能力 | 可复用范围 | 自主工作与不确定性 | 与创新的关系 |
|---|---|---|---|---|
| CodeHelper Electron／CodeMirror／SQLite | [package.json][ch-package] 与 [schema.sql][ch-schema]：桌面壳、编辑器、原生 DB、提交与错题表 | 整仓路线保留编辑、持久化、IPC、备份和 Provider | 原生 SQLite ABI 与打包未本机复现；新证据／暴露／假设表需独立迁移，不能只覆盖 ai_analysis 字段 | 成熟产品复用，不能算原创 |
| CodeHelper runner | [codeRunner.ts][ch-runner] 有超时、输出限制、并发与平台监督逻辑 | 桌面多语言时保留完整监督；适配函数测试协议 | [problems.ts][ch-submit] 当前汇总提交不足以留全部逐用例证据；需捕获、版本化和完整性标记；实际平台兼容未测 | 生产事实基础，不自动产生正确根因 |
| CodeHelper AI 接口 | [apiKeyStorage.ts][ch-key] 使用系统 safeStorage；现有 Provider／请求生命周期可参考 | 桌面主进程管理 Key 和模型请求 | 新诊断 schema、失败／取消状态、验证结果与 prompt 版本要自己做；不能把模型流式文本先展示成确定结论 | 调用接口不构成新机制 |
| Pyodide | [module Worker 说明][py-worker]与[API][py-api]支持独立线程内 Python 调用 | Python 小函数题运行时，消费官方包，无需 Fork／编译 CPython | 首次加载、超时取消、Worker 重建、stdout、内存、包兼容和残留状态需验证；Worker 不等于敌对代码安全隔离，浏览器 JS／网络桥接需限制 | 降低部署依赖；不会替你做判题与因果核验 |
| SmartCode | [执行覆盖][sc-overlay]、三级提示、技能与推荐链 | 参考实际 verdict 优先于模型、fallback 和提示审计 | 已读 runner 是 subprocess，不是完整安全沙箱；未配置题可 LLM-only；整仓 MySQL／认证不必引入 | 强基线与设计参考；原因核验须另做 |
| OpenTutor | [loom_mastery][ot-loom]、[Socratic 状态机][ot-soc]、两题对照和派生题 | 参考数据关系、教学状态；纯函数可经适配独立复用 | BKT 参数并非本场景已校准；编程评分当前 LLM；状态与 DB／课程耦合。首批用规则即可，不必复制整个 Agent 后端 | 已有学习闭环；新价值须实测 |
| Iris | 提示契约、测试反馈输入、快照锚点与 JSON 校验 | 提示策略、输入 DTO 与防错规则的参考 | Python 3.13、宿主回调及完整依赖不适合为几个提示全量部署；确定性检查只能检查明确形式，语义泄题仍需评估 | 已有④与部分 B；加三级提示不是新点 |
| ts-fsrs | [models.ts][fsrs-model]／[fsrs.ts][fsrs-api]的 Card、日志、排程接口 | 可选复习调度，独立保存事件与算法版本 | 正确映射有意义的 review event；旧 SM-2 不能无损迁移；回忆预测不是技能概率 | 可删除的辅件，不是核心创新 |

CodeHelper 现有 SQL 文本归一化比较不是查询语义等价证明，见[提交路径][ch-submit]。当前研究聚焦 Python 小题时不引入 SQL 执行器；以后通过 adapter 分离。

许可方面，本轮直接查到 [Artemis 根 MIT][art-license]、[CodeBenchGen 根 MIT][cb-license]、[EvalPlus 根 Apache-2.0][ep-license]；仍不自动覆盖任何题库数据。原候选的 MIT／MPL 与数据权利边界沿用[复用策略](<../reuse_strategy.md>)。不要求部署多套平台或训练自己的大模型；也不要求把所有参考项目代码复制到一起。

## 6. 三方案的工程可行性与效果可证明性分开

| 检查项 | A | B | C |
|---|---|---|---|
| 成熟技术足够吗 | 足够实现有限题集闭环；不保证自动认知诊断准确 | 足够实现受限证据核验；任意自然语言因果不保证 | 足够实现模板生成、执行和目标变异检查；全自动语义不保证 |
| 直接基础复用 | 编辑／执行／事件存储／审核题包 | 执行器、模型 Provider、协议校验 | 执行器、参考题包、差分／变异方法 |
| 必须自主开发 | Gap 确认规则、跨题映射、独立资格、纠错传播 | 断言类型、版本绑定、反证规则、不确定状态和用户处理流程 | 冻结预言机、目标变异定义、检查状态、题包审阅与导出 |
| 明显不确定性 | 人的误解识别、等难新题、外部辅助与真实迁移 | 受支持假设覆盖率、模型预测质量、拒绝过多 | 参考真值、目标有效性、等价变异、生成共错 |
| 需要大数据／训练吗 | 首阶段不需要；小型标签集与专家／用户验证必需 | 不需要自训；需多种错误和正确程序做评估 | 不需要自训；需目标误解库、独立参考和人工审题样本 |
| 能否独立测试模块 | executor、确认器、选题器、观测资格与状态转换可分开 | 引用／版本、事实断言、反证、输出门控可分开 | oracle、输入前提、目标变异、概念审核与接受规则可分开 |
| 能否增量接入平台 | 可以新增事件和单一流程入口；共享状态需严格控制 | 最适合做独立核心＋宿主 adapter | 可先作离线题包检查；无需重构学习平台 |
| 技术可行而效果难证 | 流程跑通≠学习迁移；新题效度与保持须用户研究 | JSON 核验通过≠解释正确；需要人工错因标注与强基线 | 构建全绿≠教学合格；概念效度和教师减负需实测 |

不重构平台的前提是把事实采集、诊断状态和观察规则放在独立模块，用 adapter 接 CodeHelper 提交与 DB；不能先让旧自评路径和新独立观测都写同一个 mastered 位。另一个可行底座是独立小应用＋Pyodide＋单用户事件存储，是否更好由下一轮环境与协议实验决定。

## 7. 拟议验收对象与停止条件

先验 executor 的事实完整性与重放，再验 B 的错误断言处理，再验 A 的误解确认和独立资格；C 先检查人工题包而非自由生成。每步独立失败时可停止扩大范围。

如果 B 仅提高引用有效率、不能减少实际错因误判，收回“高可信原因诊断”主张；如果 A 的追问不优于人工选概念，保留固定训练与观测工具；如果 C 的目标变异检查不优于成熟通用工具＋人工审核，作为普通质检模块，不当核心创新。具体实验门槛见[最终建议](<final_combination_recommendation.md>)。
