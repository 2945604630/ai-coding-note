# 最终组合建议：有条件进入实验，尚不正式认定创新

日期：2026-10-08。本轮已阅读原六份报告，针对性补查源码和五项直接先例，完成七功能矩阵、十个静态案例和架构比较。**没有开展原型、运行案例、Fork、安装上游依赖、制作 UI 或部署。截止时间未参与筛选与评分。**

## 1. 清晰决策

**首选组合：结构 IV，即收窄的结构 I。** 以 A 的①②③学习闭环为产品主线，以 B 的有限证据核验为核心，采用固定、人工审核的训练与验收题包；C 只负责离线题包质量检查。④按需提供受限提示并记录暴露。它是下一轮最值得证伪的实验方向，不是已经证明有创新的正式选题。

**备选：B 单独的高可信诊断工具。** 如果追问和独立新题效度不成立，或学习流程增加的操作得不到用户认可，保留程序假设核验、追问、用户手写修复验证和回放，不声称改善学习掌握。它在 A／B／C 单独形态中最值得优先验证，也最容易形成独立可复用模块。

**暂缓：C 独立题工厂、完整 B＋C 双主线、A／C 双产品、SQL 和自动补丁学习流程。** 理由是已有机制重叠、独立目标与预言机难点、用户需求和协同尚未证实；不是因为开发窗口长。C 仍有长期研究空间，但必须先证明目标错误闸门比成熟通用测试＋人工审核有额外收益。

**目前没有一个组合已被证实具有足够明显的创新或效果优势。** 最有希望的是有限范围内的证据与学习观测规则，所有正式创新表述都应以实验结果和先例对比为条件。若强基线同样有效，缩减机制或不以这些组合为参赛核心，不靠功能堆叠强行推荐。

## 2. 为什么推翻宽泛创新主张

最关键修正是 OpenTutor 不只是有诊断、派生题和 BKT 模块：其[提交路径][ot-submit]已经连接分类、自动派生和概念更新，[错题路径][ot-wa]已有原题／简化题对照诊断。SmartCode 的[技能流程][sc-submit]已考虑提示次数，且有更新后推荐；[执行覆盖][sc-overlay]已把真实结果置于模型 verdict 之上。Iris 的[干预实现][iris]已检查快照行引用与输出状态。

另外，Artemis 的[变式核验源码][art]已有 solution／template 构建、测试引用与语义一致性检查；[官方文档][art-doc]明确教师仍要审阅教学目标。[SMoL Tutor 论文][smol]有误解解释和同概念后续题，[HypoCompass v5][hypo]有假设、区分性测试和人工核验，[EvalPlus 变异工具][ep]有测试检测错误程序的既有方法。

因此，“完整闭环”“真实执行上下文”“提示阶梯”“生成后运行”“加 mutation”是已有基础能力。创新审查不能只和裸 ChatGPT 提示比较，也不能把上一轮没检查到的路径当成不存在。

## 3. 前两名的支持与反对

A 单独为 76，B 为 80，C 为 72；规定结构 I／II／III 分别为 79／69／75；补充收窄结构 IV 为 83。详细逐项依据与不确定性见[架构量表](<architecture_comparison.md>)。这些是设计潜力分，3～4 分差距不构成确定优势，不能写成比赛得分或实测结果。

## 4. 功能归属和自主成果边界

| 归属 | 保留能力 | 边界 |
|---|---|---|
| 同一核心机制：①②③ | 有效证据、有限程序原因假设、误解确认、目标训练、合格独立观测、错误更正传播 | 同一数据链，分别的模块与接受规则；不让 LLM 直接把失败写成知识漏洞或 mastered |
| B 独立核心 | 证据与版本校验、有限预测反证、状态及回放接口 | 可以供 A 或其他宿主调用，不维护第二套重复 diagnosis |
| ④ 可选策略 | 受限提示、固定追问、暴露记录、必要的非泄题检查 | 动态提示可删除；所有目标题帮助改变独立资格，不能边提示边认定独立 |
| ⑥ 后台工具 | 固定题包审阅、目标变异体、独立参考、有限参数检查 | 首版不必自由生成；审核状态缺失时 hold；成熟测试方法与参考题归上游 |
| ⑤ 插件方向 | SQL 专用夹具、结果语义、反例 | 不把文本归一化当等价证明；没有 SQL 用户需求时暂缓 |
| ⑦ 另一工作流 | 开发者补丁版本与回归接受 | 不进入本次独立学习验收；AI 精确修改属于辅助 |
| 排程／追踪 | 可选 ts-fsrs 或简单复习队列 | 调度不是能力证明；首阶段不需要 BKT 校准、pyKT 训练或知识图谱 |

最有希望形成的自主贡献是：**限定断言类型的核验与更正规则＋独立观测资格协议＋同症状不同原因、错误解释、无效题包的开放评测集**。开放价值要由第三方可独立消费、复放并理解结论范围体现，不靠引用项目数或使用大框架。

局部重复能力——输入约束、executor、反例执行、题包版本、概念词表——只保留一套实现。不得把①的假设反证与⑥的教学质量批准当成同一个判定；⑦的代码修复和③的人的能力检查也不能合并。

## 5. CodeHelper 是否仍是最合适基础

**不能继续无条件推荐整仓 Fork。** 它仍是候选中适合桌面编辑、错题和本地多语言执行的基础，但本轮收窄到 Python 小题后，完整工作台会带来原生 SQLite、打包、草稿／工作区状态、旧掌握逻辑与多个入口的耦合。它已存在的错题与 AI 复盘不能帮助证明新增机制原创。

当前优先比较两条实验路线：独立应用＋Pyodide，或保留 CodeHelper 并以 adapter 接入独立核心。目标 Windows 上谁能稳定保留执行事实、处理取消与异常、导出相同协议，并使核心改动范围更清楚，谁更合适。若多语言／桌面文件需求明确且 CodeHelper 基线可复现，则保留；若仅做 Python 函数题且 Worker 的兼容／重置可行，独立路线更简单。

不同时引入 Electron、Next、FastAPI、MySQL、Redis、Weaviate 和多个执行器。SmartCode／OpenTutor／Iris 主要作为强基线与机制参考；ts-fsrs 是辅助模块，不是选择底座的决定因素。源码、题面和依赖许可分开记录，根 MIT 不自动授权外部题库素材。

## 6. 最易被替代的所谓创新

| 表述 | 为什么不足 | 更简单或已有替代 |
|---|---|---|
| AI 自动分析错题／完整学习闭环 | 已有 CodeHelper、OpenTutor、SmartCode | 改现有路由或用固定概念题 |
| 把 stderr 与测试结果放进 prompt | SmartCode／Iris 等已做 | 事实覆盖模型判决、普通测试报告 |
| 对证据 ID 和代码行做校验 | Iris 已有快照锚点检查；引用存在不证明原因 | 输出 schema 与范围校验 |
| 三级提示、Socratic、FSRS、BKT | 已有提示合约、教学状态与追踪／调度 | 固定提示、简单队列、现成模块 |
| 生成变式并检查参考通过 | Artemis／CodeBenchGen 已有生成与执行修复 | 人工模板＋参数变式 |
| 变异测试证明题目质量 | 方法成熟，普通变异不等于目标误解 | EvalPlus／成熟 mutation 方法＋人工审题 |
| 换故事背景即迁移、原题 AC 即掌握 | 指标不对应要证明的能力 | 未暴露题族、独立资格与延迟观察 |
| 多 Agent 相互检查保证正确 | 共享错误题意和模型共错仍在 | 冻结独立参考与明确 not_checked 状态 |

## 7. 下一轮最需要的六项实验

以下是**待用户决定进入原型阶段后**的实验设计，当前均未执行。数字是建议规模和工程门槛，不是已有结果或领域标准；开始前应冻结输入、基线、主要指标与判定规则，不能看结果再改目标。

### E0：执行事实与底座可复现性

同一目标 Windows 设备，对 CodeHelper 原始基线和独立 Pyodide adapter 使用相同的约 12 个已审核小程序场景：正常、全负初值、端点、覆盖、异常、无限循环、超量输出、取消、残留变量、连续执行、非法输入和环境缺包。只使用已审核运行流程，不自动执行下载的安装／执行脚本。

比较输入／stdout／stderr／状态完整性、超时取消、重放一致性、冷启动、状态残留与协议改动范围。**退出条件：** 能稳定区分 WA、运行错误、超时和环境失败；所有记录包含版本与完整性；不能实现的场景明确标 unsupported。未通过前不测试模型效果或增加功能。

### E1：B 是否超越事实覆盖和引用校验

建议人工整理 60 个程序案例：40 个错误、20 个正确或环境问题，覆盖有限错误族；包括同症状不同原因、多原因、有效引用上的错误解释、过期证据和无法唯一判断。至少两名能读代码的人分别标注程序原因、可反驳预测和允许的待定范围；人的知识漏洞不能从代码标成真值。

四组采用同一模型／版本、同一题意与证据包、尽量等调用预算：自由文本；SmartCode 式执行事实覆盖；事实覆盖＋Iris 式引用存在检查；完整有限预测核验与状态规则。所有组都拿到同等事实，避免把上下文更全的优势当机制优势；另外报告新增执行／交互成本。每个案例可重复 3 次观察模型波动。

指标同时包括错误原因断言率、正确原因覆盖率、正确程序误报率、有效反证率、待定率、额外调用／时间。不能用“全拒绝”取得低误诊。**拟议门槛：** 无效／过期引用不能作为已支持断言；与最强简单基线相比，错误归因须出现可重复的下降，且覆盖率没有实质恶化。若需要数值工程目标，可预注册“误归因相对下降至少 20%、正确诊断覆盖下降不超过 5 个百分点”，但小样本结果只能筛选机制，需报告计数、成对差异与不确定性，不能当定论。

### E2：A 的误解确认与独立资格能否阻止错误状态

先以约 24 条人工设定事件轨迹检查：错误程序但追问正确；两原因竞争；辅助后原题 AC；请求验收提示；验收题看过答案；未知外部辅助；环境失败；新题题包过期；新题不匹配；诊断更正；训练题与验收题同族；正常首次独立新题通过。

对照自评／原题 retry／提示扣分规则和新资格规则，检查是否把辅助或无效题事件误计 independent，是否撤回基于错误确认的推荐，是否只记录限定观测。**退出条件：** 所有已知不合格轨迹都不能进入独立观测；unknown 不装成 independent；正常合格轨迹仍能进入。此实验只验证状态规则，不能证明用户真实学习。

### E3：C 的目标质量闸门有没有必要增量

建议 60 个可审阅题包：20 个合格、20 个弱测试、10 个参考／测试共错、10 个偏题。先用人工注入的已知缺陷验证机制，再另外检查自然生成题；不要以容易的注入缺陷代替真实生成分布。

对照三层：参考通过＋starter 失败＋引用检查的 Artemis 式基础闸门；基础闸门＋通用程序变异；基础闸门＋独立参考＋人工确认的目标误解变异与概念检查。记录弱题误放行、好题误拒、目标变异存活、偏题与人工修订时间，排除等价／无效变异。

**退出条件：** 目标闸门在通用变异基线之外识别有解释力的目标漏检；必要检查不可用时不会宣称合格；教师总审核工作没有因复杂闸门显著增加。否则 C 保留为普通后台，不作为核心创新。

### E4：小规模学习流程和未见题效度试验

先让专家审核训练／验收题的目标、难度、提示暴露与题族区别，再建议 10～16 名目标学习者参与探索性试用。使用不同概念、平衡任务顺序、相同练习时长，比较“固定诊断问＋人工映射训练”和“核验确认＋同目标训练＋独立资格流程”。两组都使用经审题包，避免题目质量混淆机制。

记录未见题首次表现、解释量表、提示依赖、操作负担；可加 5～7 天后另一个未暴露任务观察保持。明确外部辅助自述与 unknown，辅助修复不计独立通过。**退出条件：** 题目确有目标效度，用户能完成流程并认为附加步骤值得；观察到的改进应与错误训练减少等机制一致。小样本用于检查可行性和估计效应，不足以承诺长期掌握或一般人群的因果收益；正式效果结论另需预注册、合理样本与控制条件。

### E5：自主模块是否真的能被另一个宿主复用

用独立的 JSON 题包与案例文件调用 B 核心，不启动学习 UI，不访问 CodeHelper／OpenTutor 私有表；随后通过一个不同宿主 adapter 输入同语义记录。检查版本、错误状态、重放与导出一致，C 检查工具也不读取学习者历史。

**退出条件：** 核心不依赖宿主整数题 ID、IPC 和全局 store，错误记录可以解释，输入的旧版／非法引用被拒绝。若要采用结构 III，还需真实的外部教师／题库使用需求；当前只是设计，不已获得用户采用或贡献上游。

## 8. 正式确定选题前的条件

1. **范围成立：** 一个语言、有限错误族、明确初学者／助教任务；程序原因与人的理解目标可分开标注，不承诺任意根因或自动掌握证明。
2. **执行成立：** E0 证明事实与回放可靠，底座选择有实测依据；源码、题包、依赖来源和许可有清单。
3. **核心差异成立：** E1 相对强简单基线有增量，而非仅更多上下文、更多调用或更多拒绝。没有增量就不以 B 为新核心。
4. **学习链成立：** E2 的资格与更正规则可靠，验收题有效；E4 确認额外步骤有价值。否则选择 B 独立而不宣称 A 的学习效果。
5. **生成必要性成立才扩 C：** 固定题确实不足，且 E3 证明目标闸门有增量；不能为补齐三字母架构先做题工厂。
6. **开放贡献成立：** E5 或清楚的独立复用记录支持协议／核心／案例可被别人使用；不是全部实现绑在一个界面。
7. **表述成立：** 保留已有机制署名，报告失败与未核验状态；数据只支持限定范围时，申报也只主张该范围。

不必等所有长期效果完美才能继续工程研究，但在差异未成立前，不能把设计写成已证实自主创新；独立诊断与完整学习作品的成立门槛不同。
