# 第四轮正式产品方向决策

日期：2026-10-09。本轮不使用比赛截止时间作为取舍理由。真实模型比较按用户选择标为 **blocked**，真实学习者数据 **not_run**。本轮没有无条件 GO，完成报告后停止，等待审核。

**最新判断：A+B 自动诊断学习工作台暂不立项（HOLD）。** 保留简单练习流程和执行事实/回归复核作为低复杂度候选，C 独立题工厂维持 NO-GO。不 Fork CodeHelper，不扩题库、知识图谱、Agent 或完整平台。

## 1. 必须回答的六个问题

| 问题 | 实际结论及依据 |
| --- | --- |
| 1. B 的执行反证能否证明优于简单 AST？ | **目前不能。** 强 AST 接受正确 7、错误 2；局部执行正确 5、错误 1；guard 正确 4、错误 0。执行减少误报但丢失覆盖，且局部执行仍误接受 r11。追加函数 57/91 次；真实模型分布和用户损失权重未知。 |
| 2. 真实模型是否暴露了固定断言实验未覆盖的问题？ | **无法回答，真实模型 blocked，调用 0。** 新的非模型程序反例暴露了补偿性误归因、修复回归、严格门槛漏诊等机制问题；这些不能归功于真实模型。 |
| 3. A 是否真的需要自动误解确认？ | **必要性未成立。** 闭环可由简单版完成；复杂版脚本首次/最终目标均未超过简单版。真实 AI 候选、误解效度及学生纠偏收益尚未测量。 |
| 4. 简化版 A 能否实现大部分用户价值？ | **实现了主要功能闭环；大部分真实用户价值尚不能确认。** 同质量题包、训练、新题记录、辅助/暴露与撤回均具备。38 对 59 个脚本动作显示流程可更短，但没有用户满意度或学习提升数据。 |
| 5. 是否仍值得把 A+B 组合成学习工作台？ | **目前不足以支持正式组合产品。** 独立简单练习和按需执行复核更容易检验需求；先前“有条件继续验证”不能升级成完整工作台 GO。自动确因和自动认知诊断仍 HOLD。 |
| 6. 若无明显增量，应怎样重新定位？ | **收缩为“编程练习记录与可复核反馈”候选，或交付“诊断审计反例与复现实验”研究工具。** 前者以流程和需求验证，后者以错误归因、修复回归和拒判边界为研究对象；均不声称已证明 AI 创新。若竞赛必须有已验证的核心 AI 增量，应重新选题，不增加功能补偿。 |

13 个原因中的补偿截断标签存在争议；排除后分母变 12，AST/局部执行/guard 正确仍为 7/5/4、错误仍为 2/1/0。因此该标注边界不改变上述方向判断，仍应做外部复核。

## 2. 相对第三轮的决策变化

| 方向 | 第三轮位置 | 第四轮最新位置 |

这不是断言所有复杂机制无用，而是当前证据不足以支付其复杂度。执行在修复回归上有实测行为价值，复杂 A 在一个脚本里有纠偏价值；两者都还没有足以决定产品投入的自然分布、用户数据和整体收益。

## 3. 收缩后可保留的最小内容

选择知识点、固定题包、练习、新题记录、辅助和暴露声明、更正/撤回；需要时附上真实输入输出与修改前后回归。候选原因标待定，保留“证据不足”，不自动写成学生已掌握或存在特定误解。已有参考检查与目标错误测试服务于题目质量。

不新增自动课程、个性化认知模型、多 Agent、自生成大题库、知识图谱、自动补丁主流程或全工作台 UI。功能数量不会改变当前增量证据不足。把 B 作为按需审计候选也不表示已确认教师会使用或愿意承担成本。
