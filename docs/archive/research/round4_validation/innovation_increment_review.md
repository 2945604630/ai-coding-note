# 第四轮创新增量审阅

日期：2026-10-09。审阅依据是本轮冻结案例的受控程序执行、脚本回放与 CLI 演示。真实 AI 比较 blocked，真实学习者研究 not_run。没有补充功能来维持原 A+B 选题，也没有开展新的 C 题工厂。

**得到的是有限工程增量，尚未得到足以支持 A+B 工作台立项的 AI 或教学增量。** 强 AST 的简单加强有实际效果；执行擅长呈现行为和补丁回归，但当前因果确认仍不可靠。复杂 A 实现了可撤回追问流程，其必要性未成立。

## 2. B 的增量为何不够构成创新优势

强 AST 已保留七个正确原因。局部执行只保留其中五个，guard 只保留四个；执行没有新增覆盖。减少错误接受属于筛选收益，但它伴随更高待定率、更多执行和更多漏诊。当前未固定真实业务中错误接受与漏诊的损失权重，也未获取用户需求，不能人为加权让任一组“获胜”。

r03 证明上下文规则仍会错误归因；r11 则证明局部反事实执行也会错误归因。这两个反例使主张应从“可信根因确认”收缩为“有限候选的行为检查”。r05 说明安全修复与原因成立必须分开记录，r04 说明要求整份修复全对会漏掉贡献性原因。拒判增加不能替代因果推理。

guard 的收益还依赖额外作者设计的测试和固定规范。如果未来比较，把这份信息和人工维护成本忽略，就会把测试资源优势误算为执行或 AI 创新。当前的冻结强 AST 也没有做循环代数化简，不能把“这条规则未实现”说成“所有简单分析都无法处理”。

## 3. A 的增量为何仍待证

简单流程已实现目标选择、审核夹具、练习、新题代码选择、辅助/暴露限制与撤回。复杂流程在脚本里增加 21 个动作与 11 次追问，总体目标正确数没有增加。实际原型也能让用户跳过追问或更正目标，说明自动诊断并非闭环的技术前提。

但脚本不能证明追问永远无用：选错目标的学生可能受益，也可能因猜错或无效问题被误导。需要真实模型提出自然候选、独立教师确认目标、实际学习者给出有资格的回答，才能测纠偏收益和代价。目前缺少这些数据，没有量化“大部分用户价值”，更没有学习效果对照。

不应把“状态符合预期”“两组独立记录都是 5”“演示者选择可接受”当作学习提升、教学等效或用户接受度。演示和自动测试均明确标 agent_demo，没有进入真人指标。

## 4. C 保留的边界

第三轮 [C 结果与失败](<../mechanism_prototype_validation/experiment_c_results.md>) 以及原独立 oracle、已审核包、目标错误测试、来源和版本均保留。已有质量检查曾挡住共错、错概念和审核缺失，也曾误拒一个可用包；这些正负结果继续有效。

本轮仅为 A 编写六个固定、版本化的手工代码选择夹具，并检查其参考与目标错误。没有新生成器、自动审题 Agent、题库扩容接口或独立题工厂。本轮的 author_review_fixture 不升级为外部专家已审核状态。C 独立产品维持 NO-GO，仅保留为质量保障候选。

## 5. 已排除与仍未排除的解释

已排除“简单 AST 根本没有用”“执行日志越多就越可信”“局部修复一通过就证明根因”“必须复杂诊断才可记录独立验收”“原型能运行就代表学生受益”。这些都有实际对照或反例。

尚未排除“真实模型在自然代码上产生了 AST 无法有效筛选的错误”“执行证据能显著减少教师复核时间”“部分学生自选目标差，少量有效追问值得额外步骤”。这些目前只是可能性，不能作为立项证据。本轮未进行新文献或竞品检索，亦未证明机制在开源生态中具有原创性。
