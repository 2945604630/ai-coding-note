# F02 真实体验说明

在项目根目录 `<project-root>` 的PowerShell运行这一条命令：

```powershell
python -X utf8 -m experiments.feature_validation.F02_dynamic_questioning.cli_guard
```

默认真实Codex S1，使用现有ChatGPT产品登录、gpt-6.1-sol/high。无需复制模型回答或提供API Key。本轮已检测CLI可用且已登录；如果以后登录失效，按正常codex login恢复，已有失败记录保留。

1. 输入C01、C02或C03；回车默认C01。C01为循环边界，C02为边界与赋值两个缺陷，C03为原版/局部版的表面症状与真实偏差。无效选择会重新提示。
2. 查看题意、原码、审核对照版本及真实输出；每条证据有E编号与source_version。AI只接收这些公开事实和本次已发生的对话，不提供gold、旧评分或研究判断。
3. 等待首问，再输入自己的文字。本功能每次调用历史上约两分钟，等待时会提示正在调用；产品额度或连接问题会保存并停止，不自动重采样。没有预设教师回复替代真实调用。
4. 最多三次导师输出：首问→你的第一次回应→第二次导师输出→你的第二次回应→第三次导师输出。理解足够可在第二次就转入自行修改。三次是预算上限，不强制凑轮数，也不表示最后未答的问题已经解决。
5. 在回答框输入`/feedback 你的意见`可以记录当前回复是否切题或哪里不理解，不会消耗新模型调用；之后继续输入回答。输入`/quit`结束。Ctrl+C保留已有原文与日志；不要强行关闭整个进程窗口作为常规退出。
6. 结束后填写是否切题、是否理解系统意图、是否愿意继续使用（是/否/留空）。空白不算认可。对于最后一问，可在结束反馈或后续审核中注明是否重复、误解及等待是否可接受。

本入口只执行已审核的固定源码版本，不执行任意新代码。若你说“代码已修改”，请保留当前完整代码、实际调用和输出，供之后审核；旧证据不自动变成新版事实。模型给出“理解充分”只结束当前追问，不认证长期掌握，也不意味着已经修好。

真实键入记录独立保存在：

`<project-root>\experiments\feature_validation\F02_user_trials`

每次是新的时间/随机编号子目录，界面结束时打印完整路径。interaction.json包含原始回答、每轮具体消息/采用动作、判断依据、代码与证据哈希、逐轮输入快照、耗时、异常及反馈。calls/T01等保存官方首次原文、事件流、stderr、调用配置和核验结果；对应T01_input等在调用前保存完整输入。截断与失败不删除，缺少可取得原文时明确raw_available=false，不补假回答。

“利用上一轮信息/重复/无依据判断/泄露/自然语言版本匹配”在semantic_review初始记needs_human_review，首问相关项N/A；请勿把模型的解释或守卫放行当作自动准确率。每轮user_feedback为空表示尚未提供反馈；student_action_performed=not_observed表示没有观察真实修改。

历史模拟在原results/responses，历史工程冒烟在原user_runs；本轮回放/脚本冒烟在validation_repair/checks和engineering_runs，均不混入真实体验。当前旧runtime README/CLI_RUNTIME描述的是此前v2入口，记录路径请以本指南和启动后实际打印路径为准。
